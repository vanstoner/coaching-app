# ADR-005: The documentation site is built deterministically

**Status:** Accepted
**Date:** 2026-09-17
**Decision maker:** Product Owner

## Context

The knowledge base will grow into a site showing both documentation and delivery
metrics. An obvious approach is to have an agent generate pages on demand.

The Product Owner rejected this:

> *"I don't want pages to always have to be generated on demand, there should be
> some deterministic routine to convert the markdown into a site."*

The reasoning is sound and generalises. Agent-generated output varies between
runs. A site regenerated by an agent cannot be meaningfully diffed, may silently
rewrite content that was previously reviewed, and cannot be reproduced.

## Decision

**Agents author markdown. A build script renders it. The two never mix.**

- Markdown under `docs/` is the single source of truth.
- The build is a pure function: same input, same output. No network, no model.
- It runs identically locally and in CI.
- The site is never hand-edited, and never agent-generated.
- The metrics dashboard renders a collected metrics file — the same rule applied
  to data.

Build-time validations fail the build: broken internal links, issues referencing
missing specs, ADRs missing required sections, and specs left in Draft beyond a
configured age.

## Consequences

**Easier:**
- Documentation changes are reviewable as diffs in a pull request.
- The site is reproducible from any commit.
- Documentation rot becomes a build failure rather than a slow decay.
- The Draft-age check detects a *process* failure — specs implemented without
  approval — not just a content failure.

**Harder:**
- Requires a build pipeline to set up and maintain.
- Agents must author disciplined markdown that satisfies the validators.

**Accepted:**
- Phase 1 is plain markdown read on GitHub, which is genuinely useful alone.
  The build is added in phase 2, not up front.

## Alternatives considered

**Agent-generated pages on demand.** Rejected by the Product Owner:
non-reproducible, non-diffable, and able to silently alter reviewed content.

**Hand-written HTML.** Rejected: duplicates content and guarantees drift.

**Markdown only, no site.** Viable and is phase 1. Insufficient long-term
because the metrics dashboard needs rendering.
