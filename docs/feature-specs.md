# Feature specs

Status: **Current** (#239 S2, 25 October 2026). First retrofitted from the code at `e04fbb0` (v1.0.1), 2026-10-09.
Last updated: 2026-10-30 (release check of 2.1.0 at `b5174a8`: fixture form, child page, Plan, one fair-share rule, Waiting to build; the control vocabulary, #264; Settings sections, #263; Status and Code columns, #259, on 2.1.0)

**This is the current spec.** Specs 01–03 are archived as v1 intent
([`archive/v1-specs/`](./archive/v1-specs/01-domain-model.md)); where they differ
from this page, this page wins. One row per feature built. Acceptance criteria
live in the issue; this is the contract the code enforces today. `session` = `coaching-app/session/v1`,
`ledger` = `coaching-app/ledger/v2` (+ `/head`); since 2.0.0 both are one team's,
stored under `coaching-app/teams/<id>/` (ADR-022 D2).

**Status** (#259, Rob: "approve audit"), checked against the code of the branch it is on:

| Status | Means | The row must |
|---|---|---|
| Built | The code does what the row says | name in **Code** a file that exists |
| Built–differs: *how* | Built, but not quite as the row says | say how, and name its file |
| Ready | Criteria approved by Rob, not built | name its issue `#NNN` |
| Proposed | Criteria written, not yet approved | name its issue `#NNN` |
| Idea | Intent recorded, no criteria yet | name its issue |
| Superseded | Replaced; kept for the record | say by what |

**Code** is the one file to start reading from, not every file involved.
What is not built yet is under [Waiting to build](#waiting-to-build), by the
issue's `target:` label (#240 Q5); when it ships, its line becomes a row here
in the release PR. `docs/process/validate-docs.py` checks both in CI.

## How the figures are worked out

The same words as Settings › Player minutes › About the figures (`src/app/aboutFigures.ts`, #261 AC13); `aboutFigures.test.ts` fails if they differ.

<!-- about-figures:start -->
1. **Minutes on the pitch in a match.** Add up every spell on the pitch, in goal and outfield together. Bench time does not count. The clock runs through stoppages, so everyone on the pitch keeps gaining time. If a period ran over and was ended "at planned time", the overrun is left out.
2. **Matches that count.** This season's matches you ended with End match, not left out, not test or void, in the season's format (another format only if you counted it, with a note). The Squad tab's "Include reconstructed matches" switch can leave reconstructed ones out.
3. **A child's matches.** The counted matches they were at: here at kick-off (even if on the bench all match), played, or arrived late. A missed match is left out of everything below.
4. **Minutes a game.** Their minutes in those matches ÷ how many there were. Shown to the whole minute.
5. **The squad average.** Add up each child's minutes a game and divide by the number of children. Each child counts once, however many matches they played. Main keepers (when the squad has one), fill-ins and children who have left are not in it. This is not all the minutes ÷ all the appearances; that gives a slightly different number.
6. **Fairness: the gap a game.** Each child's minutes a game − the squad average, both to the whole minute. "Everyone within N min a game" is the widest of these.
7. **Under or over the average this season.** (Squad average − their minutes a game) × their matches from step 3, rounded once at the end. The same as: for each game they played, the squad average minus their minutes, added up. 5 min or more under puts them "Next in line for more time".
8. **A match's fair share (the match report).** The minutes on the pitch of the children there, ÷ how many of them there were. Main keepers are not in it; fill-ins are. "vs share" is their minutes − the share.
9. **The Plan's fair share.** The same as step 8, from the planned minutes, over the children available for the match.
10. **Settings › Player minutes** adds up every match not left out, including ones not ended and other formats, so its totals can be higher than the Squad tab's.
