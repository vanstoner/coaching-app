### 1.3 State architecture

- **Centralised, not fragmented.** One owner (`App.tsx`), pure rules in `src/app`. There are no competing contexts or hooks. This is the app's biggest strength.
- **But the live match is mutable shared state.** `MatchEngine` mutates `match.state` in place (`substitute`, `startQuarter`, `endQuarter`). React never sees the change; the shell calls `persist()` and, where nothing else changes, `repaint()` (`App.tsx:827`).
- **Aliasing.** `openMatch` (`src/app/matchLifecycle.ts:136-143`) builds the live state from the stored match's own `quarters`, `appearances` and `benchStints` arrays. So the engine also mutates objects inside the `matches` React state. Two of the comments in `App.tsx` (match day 4, `matchesOnRelease`) record defects from exactly this.
- **Memoisation keyed on a mutated object.** `LineupScreen.tsx:135` uses `useMemo(..., [engine, state, players])`. `state` never changes identity, so it is only correct because `App.tsx:1254` passes a new `players` array on every render.
- **`persist` depends on 12 values** (`App.tsx:380`), and an effect (`:448`) runs it whenever any of them changes. Any state change rewrites the whole session, including each keystroke of the team name (`SettingsScreen.tsx:93`).

### 1.4 Local persistence

| Check | Finding |
|---|---|
| Write races | Ledger: serialised per store (`ledgerStore.ts:198`). **Session: not queued**; each `persist()` is a separate `setItem`. AsyncStorage on Android runs writes in order on one database, so last-write-wins holds in practice. Nothing in the app guarantees it. |
| Migrations | Present and tested for the session (`MIGRATIONS`, schema 6, 22 migration tests) and the ledger (v1→v2, forward-compat tests, frozen 1.0.0 release fixture in `src/app/fixtures/release-1.0.0/`). Good. |
| Launch errors | `loadSession` and `openStoredLedger` catch read errors. **But `loadSession` folds `corrupt` and `too_new` into `null`, and the shell then saves an empty session over the stored one.** Reproduced → **[#173](https://github.com/vanstoner/coaching-app/issues/173)**. |
| Validation | `validate()` checks arrays exist, not their elements (`players as Player[]`). One malformed match rejects the whole session, which then hits #173. |
| Failed writes | Ledger: `commitLedger` (`App.tsx:236`) updates the in-memory copy before the write and ignores `false`. A failed write is not retried until the records change. |
| Growth | Measured with the Test kit season (9 matches, 10 players): **session 183 KB, ledger 116 KB**. About 20 KB a match. A 30-match season is about 600 KB, and nothing rolls a season over. Both values are rewritten in full on every sub, goal and keystroke. Legacy AsyncStorage on Android keeps each value in one SQLite row, and Android's cursor window is about 2 MB. Around the third season the session nears that, a read can fail, and the failure feeds #173. Not verified on a device. |

### (b) Match setup

- **Fixture:** Home → `fixtureForm` → `saveFixture` (`:524`) → `newMatch` (`matchLifecycle.ts:56`) snapshots format, length and periods, and marks the active squad available → `persist({ matches, state: live })`.
- **Plan:** `plan` step → `PlanScreen` → `savePlan` on every edit (`:589`).
- **Open:** `openFixture` (`:669`) → `openMatch` (rebuilds `MatchState` from the stored copy, **aliasing its arrays**) → `releaseMatch` folds any previously held match into `matches` first → `openDestination` picks squad, lineup, clock or summary.
- **Play now:** `playNow` (`:726`) → squad editor if too few players, else `beginMatch` → held, not yet in `matches`.
- **Lineup:** `LineupScreen` seeds from the plan (`lineupFromPlan`) or the suggestion (`suggestLineup` by least minutes). Attendance toggles call `setHereToday` → ledger `attendance` + `repaint` + `persist`.
- **Kick-off:** `startQuarter` (`:893`) → `fillSquadAtKickoff` → `engine.startQuarter` sets the anchor `runningSinceWallClock`, opens Appearances and BenchStints, and sets the match `in_progress` → `persist({ periodSubs })`.

### (c) Live operations

- **Clock:** `ClockScreen.tsx:141`, a self-rescheduling `setTimeout` to the next displayed second. `forceRepaint` only. All values come from `deriveClockView(engine, state)` (anchors).
- **Due sub:** `dueSubs(subPlan, elapsed)` → coach taps Done → `makeSub` (`App.tsx:916`) → `engine.substitute` closes and opens stretches at the same match-elapsed instant → `noteLateArrival` → `markDone` → `persist`.
- **Drag or tap move:** `PitchView` PanResponder → `liveMove` (`teamSheet.ts`) → `onLiveMove` → `engine.swapPositions | substitute` → Undo toast (10 s) runs the reverse move.
- **Goal, save, conceded:** tap sheet → `recordEvent` → engine checks the player is on the pitch, or is the keeper → Undo = `withdrawEvent` with `UNDO_NOTE`.
- **Buzz:** an effect after every paint runs `checkBuzz(log, …)`. Only in the foreground; once per sub per period; the log lives in the shell's ref so leaving the clock does not re-buzz.
- **Leave:** `goHome` → `persist` → `fixtures`; the match stays held and current.

### (d) Finalisation and storage

- `endQuarter` (`:1002`) → `engine.endQuarter` freezes `accumulatedMs` and closes every open stretch at match-elapsed → clears the sub plan → `persist` (the ledger records the newly closed intervals) → `lineup`, or `playing` after the last period → "See the minutes" → `summary`.
- `closeMatch` (`:864`) → `endMatch` → `engine.completeMatch` (`completed`) → `persist` → ledger `match` status.
- Summary Back → `releaseMatch(null)` folds the held match into `matches` → `fixtures` → `persist`.
- Attendance correction on the report: `correctMatchAttendance` appends a noted ledger record.

### 3.2 Safe expansion architecture

```
App.tsx (shell)            routes, owns the store, mounts feature modules
  ├─ src/match/            live match: reducer(state, action) over an immutable MatchState
  │                        engine stays pure; actions = startPeriod | sub | swap | record | withdraw | endPeriod
  ├─ src/season/           read-only views over the ledger (squadViews, childSeason, analysis) — already pure
  ├─ src/fixtures/         planned matches and plans
  └─ src/features/<v2>/    each v2 capability: its own state slice, its own storage key,
                           reads the ledger through the ADR-017 gate, never writes the session
```

Rules for v2 modules:
1. **New data gets a new storage key**, versioned like the ledger, never a field squeezed into the session document. A v2 bug then cannot corrupt v1's season.
2. **Read v1 data through pure functions only.** `squadViews`, `seasonRows` and the ADR-017 gate already exist. No v2 module receives `ledgerRef` or `setMatches`.
3. **The live match becomes a reducer.** `useReducer(matchReducer)` with the engine returning new state, not mutating. This removes R7 and the `repaint()` calls, makes memoisation honest, and lets one save middleware queue writes (fixes R11).
4. **Feature flags by build.** `showTestKit` / `currentDistribution()` already exists; gate v2 screens the same way so a PR beta can carry them while Heart FC Coach does not.
5. **Each v2 screen is a `Step`** with a `backFrom` entry and a test in `tabs.test.ts`, so it cannot be a trap (CLAUDE.md "every screen needs a way out").
